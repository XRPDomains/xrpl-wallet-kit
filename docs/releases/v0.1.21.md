# XRPL Wallet Kit 0.1.21

## Ledger Signing Hardening

- Correct the multisign payload sent to the XRP app. Applications still prepare
  one immutable transaction before collecting signer contributions.
- Verify default device signatures locally before returning a blob or submitting.
- Preserve XRPL RPC errors and prevent submission after a Ledger session changes.
- Invalidate late connection/account-discovery results and isolate transport cleanup.
- Preserve transaction flags while adding `tfFullyCanonicalSig` for single-sign
  compatibility with XRP app 2.3.2. Device errors include status/app diagnostics.

## Experimental Batch

Opt-in, single-account All-or-Nothing Batch supports 2-8 inner transactions through
the existing signing methods. Preparation checks BatchV1_1/fixBatchV1_2 amendments,
validates inner transactions and bounds fees. Confirmation requires validated
inner results with matching parent and ledger, not just outer success.

Install a Batch-compatible xrpl.js SDK (locally validated with 4.7.0), explicitly
allowlist adapters and test real wallet acceptance before exposing this flow.
Ledger Batch support is not confirmed. Existing non-Batch flows remain unchanged.

## Integration And Testing

- Unified React/vanilla wallet console on port 5173 with a shared wallet session.
- Separate Batch prepare/review/sign-only/submit controls, real-funds consent and
  prepared-payload expiry.
- Updated Batch guides and GhostSig transaction examples.
- Coordinated package versions, browser bundles and website navigation: 0.1.21.

Validation: 384 automated tests, browser bundle smoke, package/version release
