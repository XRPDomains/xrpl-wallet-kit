# XRPL Wallet Kit 0.2.0

## Xahau

- Configure `network: "xahau-mainnet"` or `"xahau-testnet"` in the all-in-one client;
  Xaman, GemWallet and Xyra use the matching chain configuration automatically.
- Ledger is explicitly opt-in on Xahau and requests the XAH app on the device.
  Payment and auto-open XAH have maintainer-reported live acceptance; other
  transaction types and device/app versions still require separate testing.
- Native Payment, Invoke/HookParameters, TrustSet, offers, AccountSet and URIToken
  transaction support uses a dedicated codec with complete intent/signature
  verification before optional RPC submission. A positive fee ceiling is required.
- Browser/CDN loads a separate minified `xrpl-wallet-kit-xahau.runtime.js` only
  when needed. Self-host it beside the IIFE or use matching versioned CDN assets.
- SetHook, Batch on Xahau, multisign and chain-bound Xahau authentication are not
  supported. Safari/iOS Xyra popup behavior still requires live acceptance.

## Wallets and Website

- Xyra is exported by client/browser; explicit XRPL selection remains required.
- Theme Builder includes Xyra and XRPL/Xahau mainnet/testnet selection. Wallet
  lists and generated configuration follow the selected chain and fee policy.
- Xahau documentation, adapter navigation and installation guides are aligned.
- Mainnet badges are hidden for both XRPL and Xahau; testnet badges remain visible.

## Compatibility and Security

- Client localStorage is scoped by chain/network, including XRPL networks. Legacy
  XRPL sessions migrate once only when registered network identity matches;
  provider verification still applies. Logout prevents remigration. Old transaction
  history is retained in legacy storage, not automatically copied. Custom storage
  objects are unchanged; scope those yourself when running multiple applications.
- Both `supportedNetworks` and `supportedChains` restrictions are enforced.
  Empty lists deny access; custom Wallet Standard mappings must be registered.
- GemWallet XRPL sign-only verifies signed blobs and enforces a default
  1,000,000-drop fee cap, configurable through `xrplMaxFeeDrops` or the request.
- Non-XRPL auth challenges include chain identity. Backends must pin
  `expectedChainId` before accepting non-XRPL proofs. This does not add a Xahau
  proof verifier or change raw message bytes.
- Existing dependency audit exceptions remain unresolved, including elliptic and
  node-forge. This release does not claim a clean dependency security audit.

All Wallet Kit packages in this release use version 0.2.0. Update pinned packages
together. XRPL network IDs and the primary connection/signing APIs are unchanged.
