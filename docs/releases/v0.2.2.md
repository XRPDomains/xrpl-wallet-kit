# XRPL Wallet Kit 0.2.2

## GemWallet on Xahau

- Avoid repeated address/network approval requests during transaction signing.
  The signed blob is still checked for its signer, NetworkID, transaction intent,
  fee and expiry before it is returned or submitted. Cancellation remains enforced.
- Sign-only and sign-and-submit flows retain their existing API. The repeated
  popup fix has been confirmed in live GemWallet testing.

## Wallet UI

- Show the active chain/network in the footer only, removing redundant testnet,
  devnet and custom-network badges above the wallet list.
- Preserve spacing between wallet items.
- Compact balance text on the connect button while retaining the full resolved
  balance in the account panel and tooltip.
- Automatically hide button balance text when the available width is too small,
  and restore it when the button widens. The account panel remains unaffected.
- Keep the last known balance visible during refresh and transient RPC failures,
  with a tooltip identifying stale data. Clear it when the account/network changes.

## Docs and Local Console

- Pin website previews to their matching SDK release without probing CDN latest.
- Document browser IIFE usage and the automatically loaded Xahau runtime.
- Route local-console Xahau balance/reserve reads through its same-origin proxy
  to avoid upstream HTTP CORS restrictions. This is a local-console fix, not a
  change to RPC CORS support for deployed dApps.
- Allow the local console port to be selected with the PORT environment variable.

No breaking API changes. All Wallet Kit packages use version 0.2.2; update pinned
packages together. When self-hosting browser assets, use the IIFE bundle and
Xahau runtime from the same release.
