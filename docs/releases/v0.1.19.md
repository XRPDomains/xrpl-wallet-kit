# XRPL Wallet Kit v0.1.19

Coordinated release of all 15 public `@xrpl-wallet-kit/*` packages.

## Highlights

- Opt-in transaction preflight policies with immutable transaction checks.
- Request lifecycle diagnostics, cancellation, timeouts and stale-operation cleanup.
- Adapter conformance test utilities under `@xrpl-wallet-kit/core/testing`.
- Opt-in XRPL Wallet Standard discovery with dynamic wallet/account updates.
- Multisign signature verification, deterministic signer combination, trusted-policy quorum/fee checks and one-shot submission helpers.
- Signing/session race fixes, React lifecycle fixes, selective integration docs and mobile theme-builder/navigation improvements.

## Migration Notes

Default Ledger multisign signing requires a fully prepared source Account,
Sequence/ticket fields, Fee, LastLedgerSequence and any network-specific fields,
with SigningPubKey empty and no signature fields. It no longer autofills each
contribution. Prepare once; any intent/fee/expiry change requires a new signing
round. Existing single-sign flows are unchanged.

Discovery and preflight are opt-in. Resolve multisign authorization from trusted
validated ledger state; helpers do not fetch or refresh signer policies.
Cancellation after submit dispatch cannot undo submission. Reconcile the hash
before retrying. See [multisign integration](https://github.com/XRPDomains/xrpl-wallet-kit/blob/main/docs/multisign.md)
and [discovery integration](https://github.com/XRPDomains/xrpl-wallet-kit/blob/main/docs/wallet-discovery.md).

GhostSig is not included; adapter integration remains tracked in #34.

## Validation and Known Limitations

- 328 automated tests pass, including multisign, signing/session and discovery tests.
- Dependency boundary checks, TypeScript build, website build and functional readable/minified browser smoke checks pass.
- Live Ledger hardware and funded multisign testnet tests remain manual integration checks.
- Existing dependency audit reports 24 advisories, including 1 critical. This release does not claim a clean dependency security audit or apply unrelated forced upgrades.

## Install

```sh
npm install @xrpl-wallet-kit/client@0.1.19
```

The browser widgets continue to load `@xrpl-wallet-kit/browser@latest` through
jsDelivr. All internal kit dependency versions are coordinated at 0.1.19.
