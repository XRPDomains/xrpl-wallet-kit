# XRPL Wallet Kit 0.1.23

## Highlights

- Ledger can request opening XRP directly on the hardware during explicit connection. `autoOpenApp` defaults to true; hardware confirmation, an unlocked device and an installed XRP app are still required. Ledger Live desktop is not required. Cancellation, selected-device-only reconnect and manual fallback are supported.
- New `@xrpl-wallet-kit/vue` package provides app-scoped Vue 3 bindings, with SSR-safe Vue/Nuxt integration guides.
- Passive wallet availability checks are coalesced and cached, and modal refreshes preserve keyboard focus.
- Browser Xaman authorization isolates OAuth attempts, verifies tokens with the issuer and recovers same-origin return tabs without accepting cancelled callbacks. Live mobile acceptance remains pending.
- Stylesheet nonces are applied before insertion, with browser CSP regression coverage. Packed-consumer CI now covers xrpl v4/v5, Vue and React 18/19.

## Security And Upgrade Notes

- Cached sessions cannot become connected sessions without passive adapter verification; restored identities must match.
- Legacy authentication proofs are bound to the account signing key. WalletConnect accounts must have valid classic addresses on the requested chain.
- Authentication now rejects missing nonce checks by default. Backend integrations must implement replay protection. Prefer `verifyWalletAuth` with atomic consumption of a server-issued nonce after signature verification, bound to the requester and context. Format-only inspection is explicitly opt-in and must not authorize sessions.
- Wallet URLs use an explicit scheme allowlist and reject control characters.

All 18 public packages are coordinated at 0.1.23. Existing transaction signing flows remain unchanged. Batch remains experimental; this release does not claim Ledger Batch support or universal hardware/mobile acceptance.
